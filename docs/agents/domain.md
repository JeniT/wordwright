# Domain docs

Read this when you name a domain concept in an issue, test, refactor or UI text, or when your change may contradict a recorded decision.

- **Vocabulary:** [CONTEXT.md](../../CONTEXT.md) is the glossary. Use its terms; if a concept you need isn't there,
  you are either inventing language the project doesn't use or you've found a gap to note for `/domain-modeling`.
- **Decisions:** [docs/adr/](../adr/README.md) holds the reasons behind non-obvious choices, one file per decision, grouped by area. Read the area index, then the decisions that touch what you are about to change.

# Domain docs

Read this when you name a domain concept in an issue, test, refactor or UI text, or when your change may contradict a recorded decision.

- **Vocabulary:** [CONTEXT.md](../../CONTEXT.md) is the glossary. Use its terms; if a concept you need isn't there,
  you are either inventing language the project doesn't use or you've found a gap to note for `/domain-modeling`.
- **Decisions:** [decisions.md](../decisions.md) holds the reasons behind non-obvious choices; `docs/adr/` holds the
  few written as separate ADRs. Read the ones that touch the area you are about to change.
- **Conflicts:** if your output contradicts a recorded decision, say so explicitly rather than overriding it:

  > _Contradicts "Reviewers review a snapshot", but worth reopening because…_

# A reply is always in words, whatever tools it calls (#303)

A real run came back with a conversation title and a note suggestion but no words: the server accepts a reply of tool calls alone (only an empty reply with no calls is an error), and the rules, reworded in #295 to say "do not list your suggestions again", let the model read its tool calls as the reply. The rules now say a reply is always written in words and tools are in addition to it, and the tool prompts say the same; "do not list" became "do not repeat the text of a suggested note". The evals check it (`repliesInWords`: at least a sentence once the rendered tool calls are taken out) on every case that uses a tool, and a case where the writer makes several points, so suggestions and words must both appear. If a reply still has no words, its box says "Your AI didn’t write a reply. Send a message to carry on." (not for a stopped, declined or cut-short reply, which have their own lines). The server still accepts it, so the suggestions are not lost. **Prompt changes (`prompts/brainstorm-rules.md`, `tool-suggest-note.md`, `tool-name-conversation.md`): the owner reviews them and runs the evals against a real model.**

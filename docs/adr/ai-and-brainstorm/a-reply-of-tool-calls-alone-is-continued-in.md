# A reply of tool calls alone is continued in the app (#305)

The second real-model run of the evals (after #304's prompt changes) failed in the same way: 20 of 25, every one of them tool calls with no words, so wording does not fix it. The model ends its turn after calling tools (stop reason `tool_use`) and, having said nothing, waits for the results before it writes. `brainstormTurn` (in `services/brainstorm.ts`) now handles that: when a reply has calls, no words and stop reason `tool_use`, the calls go back as a user turn with each one answered and a note to write the message in words, and what the model then says is streamed as the reply. It is one extra request, only then; further calls in it are ignored, so it never loops; the calls and token counts are the two requests' together; and the stored message is the words then the calls, so replay and the next turn's tool results are as for any reply. The words-first prompts stay (they may reduce how often it is needed). The eval harness runs this same function, so the evals test what the app does. **Not changed: `prompts/`. The owner re-runs the evals against the real model.**

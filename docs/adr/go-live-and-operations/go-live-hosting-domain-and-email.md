# Go live: hosting, domain and email (#22, #20)

- **Host: one UpCloud VM in London** (Starter plan, 1 CPU, 2 GB, 20 GB; about €6 a month), running the app in Docker behind Caddy. A UK region keeps the data map simple, and Hetzner, the cheapest option, has no UK region. DigitalOcean London was the alternative: US-owned and about twice the price for the same size. UpCloud is a Finnish company.
- **SQLite stays, and there is exactly one instance.** The rate limiter is in memory, so a second instance would split its counts; a shared store is not built for the alpha. Moving to Postgres or several instances is a later decision with its own migration. Backups are a nightly `sqlite3 .backup` copied off the machine (a plain copy of a live WAL file is not safe), plus the provider's backups; the encryption and session secrets are kept apart from the data backups. Details and the rehearsal are #17 and #322.
- **Addresses:** the app is at `app.wordwright.io`; the apex `wordwright.io` stays on GitHub Pages as the public landing page. DNS is at Gandi. Setup is #349.
- **Email: Scaleway Transactional Email over SMTP**, sent from `Wordwright <hello@wordwright.io>`; Brevo (also French, SMTP) is the fallback if deliverability is poor. Resend and Postmark were rejected because both store data in the US (covered only by standard contractual clauses); Resend's free tier and Postmark's developer reputation did not outweigh that for a service that sends sign-in links and names. Scaleway bills per recipient, with 300 emails included and €0.25 per 1,000 after, so there is no daily cap to hit. The adapter is the existing `SmtpMailer`, so a change of provider is configuration (`SMTP_URL`, `MAIL_FROM`), not code. Deliverability to Gmail, Outlook and iCloud is tested before launch (#349, #322); we could not verify Scaleway's reputation in advance.
- **No `no-reply` address.** Mail comes from `hello@wordwright.io`, which Gandi forwards to the owner (free forwarding with the domain). Reviewers receive mail from a tool they have never heard of; a real address they can reply to helps trust and deliverability. Replies are personal data, and the forwarder is a processor (#320). The address is a role, not a name, so it can be handed over. A `Reply-To` header would need a code change and is not needed while `From` is the monitored address.
- **Not decided here:** Google sign-in for production (#350), the landing page (#171), and whether to rotate `KEY_ENCRYPTION_SECRET` before launch (#169).
